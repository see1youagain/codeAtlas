# CodeAtlas 开发日志

## 1. 从教学骨架收敛为可运行系统

问题：参考项目保留了 Milvus、Embedding、文档入库等占位实现，直接复制会得到“架构看起来完整，但闭环不可运行”的 Demo。

解决：将目标收敛为代码仓库事实系统，使用确定性搜索、按行读取、SQLite 和 Git Worktree，先完成问答、审批、修改、验证的薄闭环，再根据评测决定是否引入向量检索。

## 2. 模型生成引用不可信

问题：模型可能编造 Citation ID，或者复用旧会话中的证据编号。

解决：Harness 为本轮 Tool Observation 统一生成引用编号；Reviewer 重新校验路径、行号和代码片段。没有本轮有效引用时拒绝回答。

## 3. TDD 不能只让同一个模型自证

问题：Developer 自己写测试、自己实现，可能通过降低断言强度制造“绿灯”。

解决：测试分为 Project Profile 的独立基线套件、计划审批绑定套件和修改后回归套件；Developer 无任意 Shell 权限，Reviewer 还要检查测试文件和 Diff 范围。

## 4. 源仓库不能成为 Agent 沙箱

问题：直接在用户仓库修改会污染工作区，失败后也难以恢复。

解决：源仓库只读；Runtime 维护 Bare Mirror，并按执行创建独立 Worktree。系统只允许精确替换或新建文件，不允许删除、Merge、Push。

## 5. 审批存在 TOCTOU 风险

问题：用户批准后，如果代码 Revision、计划或测试范围发生变化，旧批准不应继续生效。

解决：Approval 绑定 Plan Digest、Base Revision、允许路径和测试套件；执行前再次比较，范围只能收窄，不能扩大。

## 6. Memory 容易把旧事实当新事实

问题：历史调查可以节省 Token，但代码变化后旧结论可能过期。

解决：调查记忆按仓库隔离，并校验 Git Revision、证据文件哈希、30 天 TTL 和数量上限；召回内容仅作为搜索线索，最终答案仍必须重新调用工具获得当前证据。

## 7. MCP 权限切分

问题：把问答工具和执行工具放在同一匿名端点会扩大攻击面。

解决：`/mcp` 只暴露只读工具；`/mcp/admin` 先校验 Bearer Token，写能力还要经过 `ENABLE_WRITE`、计划审批和路径门禁。

## 8. Windows 路径与前端运行时

问题：含中文的工作目录可能未被某些命令执行器正确采纳；系统 Node 存在但未加入 PATH。

解决：命令内显式使用 `Set-Location -LiteralPath`；前端构建使用已安装 Node 的绝对 `npm.cmd` 路径。项目代码本身不依赖该本机路径。

## 9. 百度网盘同步丢失恢复（2026-10-07）

问题：工作区只剩部分源码；Git 状态显示 27 个已跟踪文件被删除，后续 Memory 版本的一批新增文件也不在 `main` 中。同时 `.gitignore` 忽略绝大多数 Markdown 和整个 `stages/`，导致文档没有版本保护。

解决：没有执行 `reset --hard`，而是比较 `main` 与本地时间机分支，从最新快照 `ef2872e` 只恢复磁盘上不存在的 39 个文件；保留 `.env`、现存文档和用户新增文件。随后重建交付文档，开放其 Git 跟踪，并执行单测、Race、Vet、双入口与前端构建。
